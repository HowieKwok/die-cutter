# 仿真机制重构实施方案

> 状态：**已实施**（阶段一、阶段二均完成，全量编译通过；运行期冒烟待现场验证）。
> 范围：彻底移除旧仿真，新增 `Frame_Simulation` 项目。
> 目标：仿真与自动走**同一条**全流程路径，上层业务不感知仿真存在。
> 实现与本文档的偏差记录见文末第 9 节。

## 1. 已确定的三项决策

| 项 | 决定 |
|---|---|
| 相机仿真形态 | A：进程内 `SimCamera : CameraObj`，不建 TCP 服务端 |
| 激光心跳 | 恢复 PLC `D1004` 写入，与控制卡 IO 脉冲共用同一脉冲沿 |
| 产能换算 | `帧延时(ms) = 60000 / 产能(片/分)`，一拍多相机并行；延时越大产能越低、画面刷新越慢 |

## 2. 目标态

- 运行模式来自本地配置文件，启动时读取一次，运行期不可切换。
- 工具栏只显示当前模式，按钮不可点击。
- `Project.Is_simulation` 字段消失；业务层不再出现任何模式分支。
- 仿真相机拥有自己的 `QueueGrabImage`，下游 `CallBackImgDataDeal` → 流程 → 显示/存图 与真机完全一致。
- 只有仿真模式才挂载"仿真"菜单入口，界面非模态。

## 5. 阶段二：新仿真机制

### 5.1 新增项目 `Frame_Simulation`

```
Frame_Simulation/
  Config/SimulationConfig.cs      模式、产能、数据目录名(默认SimTest)、PLC端口
  Config/StartupChecker.cs        相机/光源/PLC/控制卡体检，分阻断与警告
  Capture/SimCamera.cs            : CameraObj，节拍线程读图
  Capture/FramePacer.cs           产能 ⇄ 帧延时
  Plc/SimPlcServerBase.cs         生命周期 + 写值表 + 记录
  Plc/SimPlcServerFins.cs         OmronFinsServer（激光）
  Plc/SimPlcServerCip.cs          OmronCipServer（五金，需 AddTagValue 注册符号与类型）
  Log/SimRecorder.cs              相机、PLC 两个独立记录通道
  View/Form_Simulation.cs         非模态，产能 + 双记录表
```

`SimCamera` 必须实现的成员：抽象 `InitCam/OpenCam/StartGrabImage/StopGrabImage/DestroyCam/DestroyObjects2/SetTriggerMode/SetGrabState/SetGain`（`CameraObj.cs:226-316`），虚成员 `Image/IsExist/IsCameraStatue`，以及 `QueueGrabImage`。参照实现见 `CameraFLY.cs`。

### 5.2 接线点（只改这几处）

| 位置 | 改动 |
|---|---|

| `Project.Init_Dev` | 不改：`ConnectAllCam` / `StartGrabImage` 照旧，仿真对象自己决定是否真起节拍 |

## 6. 注意事项

1. `SystemParam.json` 升级兼容：老文件无 `RunMode`，必须让缺省值 = 自动，否则现场升级会误入仿真。
2. 仿真模式下体检不通过必须阻断，否则后续会去连真机或直接失败，表现为"一台坏机器"。
3. PLC 服务端必须在客户端 `Connect` 之前 `Start`，端口占用属阻断项。
4. `OmronCipServer` 需按符号注册类型（`AddTagValue(name, type, length)`）；五金 7 个 `CCD_DATA_RD.*` 类型对不上时客户端写入会静默失败，仿真记录要能看到写失败。
5. `SimCamera` 的节拍线程必须能 `StopGrabImage` 干净退出，否则退出程序时线程残留。
6. `ImageSimManage` 保留（`CameraRelevancy` 字段、标定/点检界面在用），只删生产流程中的用法。
7. `SimControl` 的流程重载删除，标定用的一次性取图保留。
8. 图片目录改动要即时生效（`ReloadImageSet`），否则仿真界面调完参数看不到变化。

### 9.2 与设计文档的偏差（实现时验证得出）

1. **`GetStates` 的实际写法**是 `Project.Instance.GetStates() && !Project.Instance.Is_simulation`，不是简写的 `!GetStates()`。
2. **`CameraDev` 的命名空间**是 `DevMgmt.Cameras.Models`，不是 `DevMgmt`。
3. **激光心跳改为内联**写在 `Communication()` 的脉冲分支里：`Server_DieCuttingCut` 不是 `partial` 类，新增辅助方法要动大文件尾部，风险高于收益。
4. **`CameraObj.QueueGrabImage` 是只读自动属性**，基类返回 `null`；所有真机都覆写它。`SimCamera` 必须自持队列并覆写，否则入队即空引用（已踩坑并修复）。
5. **送帧顺序以真机为准**：`RaiseCamCallbackStart` → 入队 → `CamCallbackEndEvent`（`CameraHKControl.get_Image` 的实际顺序）。
6. **`IsCameraStatue` 语义是"正在采集"**，不是"相机存在"，`SimCamera` 已按此覆写；`QueueGrabSurface` 在 `src/frame` 零使用，故意不覆写。
7. **`UapateSimPath` 未删除**，改名 `RefreshSimulationImagePaths`：它同时刷新 `ImageSimManage`（标定/点检仍在使用）与 `SimCamera.ReloadImageSet`。
8. **`IBIZWorkerBase.SimLoadImage` 保留为空实现**：接口方法删除会牵连所有实现方，收益不足。
9. **构建方式**：`dotnet build` 不可用（WPF XAML 不走 SDK markup compile），必须用 `build.bat`（VS MSBuild）。
