# 五金模切 换卷（Paused → Paused）设计（修订版）

> 前置文档：`docs/五金模切_运行控制设计.md`（三态与动作编排）、`docs/五金模切_帧队列与PLC发布设计.md`（帧序号代际与门控）。
> 本文只描述新增的一条状态迁移，不改变现有 Idle / Running / Paused 的任何语义。
>
> **本稿相对初稿的修订**：①宿主接口改为返回 `SwitchRollResult`，取消控制器推断降级；②`PrepareFilmRoll` 失败必须回滚，旧卷才真正"完好"；③换卷期间短暂停发布器，保证写 0 是终值；④去掉控制器对 `Project.systemInfo` 的依赖；⑤`CanEditRollName` 按 §8 修正；⑥补合片在途统计、告警清理、UI 刷新等落地细节。

## 1. 背景

五金现有动作：开始膜卷（Idle→Running）、暂停/继续（Running↔Paused）、结束膜卷（→Idle）。缺少"生产中途换卷"。

换卷的本质是**数据代际切换**，不是设备停止：流程线程、发布器、PLC 会话都不需要重建；需要变的只有膜卷号、生产路径、帧序号代际、算子参数内的跨帧缓存、统计归属。

`五金模切帧序号` 的代际机制本来就为换卷预留了语义（`Generation` 注释"停机 / 换卷 / 复位各 +1"；`Reset()` 归零三路序号、清空有效帧集、触发 `OnProductsCleared`），只是 `MetalRunController` 没提供这条迁移。

## 2. 目标与不变量

新增动作：**换卷**。仅 Paused 可用，完成后仍为 Paused。

1. 换卷不重启流程线程；不重建 PLC 会话
2. 换卷使帧序号代际 +1、序号归 1
3. 旧卷数据全部落旧卷路径，新卷从第 1 片开始
4. 换卷期间帧准入关闭；期间被拒绝的帧不计数、不告警
5. 换卷失败不产生"半卷"：要么旧卷完好可继续，要么降级结束进 Idle
6. **发布器允许在清场窗口内短暂停止**（只停发布线程，不动 PLC 连接）。初稿"绝不停发布器"与 `帧队列设计` 5.8"先停发布器再写 0"冲突，本稿以数据正确性优先

`发布器停止`不等于`结束膜卷`：结束膜卷会 `StopRun` 停流程、停发布器、清场进 Idle；换卷只停发布线程，流程线程保持挂起、状态保持 Paused。

## 3. 状态机

```
Idle ──[开始膜卷]──> Running
Running ──[暂停]──> Paused
Paused ──[继续]──> Running
Running ──[结束膜卷]──> Idle   （先自动暂停）
Paused ──[结束膜卷]──> Idle
Paused ──[换卷]──> Paused      （新增）
Idle ──[换卷]──> 拒绝（"请先开始膜卷"）
Running ──[换卷]──> 拒绝（"请先暂停后再换卷"）
```

## 4. 与现有动作的边界

| 动作 | 流程线程 | 发布器 | 帧序号代际 | 状态迁移 | 数据影响 |
|---|---|---|---|---|---|
| 暂停/继续 | Suspend/Resume | 不停 | 不变 | Running↔Paused | 无 |
| 换卷（新增） | 保持 Suspend | 清场窗口内短暂停 | +1 | Paused→Paused | 旧卷结账，新卷从第 1 片开始 |
| 结束膜卷 | Stop | Stop | +1 | →Idle | 清场回空闲 |
| 开始膜卷 | Start | Start | +1 | Idle→Running | 新建卷 |

### 5.2 SwitchRollResult

`NeedsConfirm` 只由控制器产出，宿主不会返回；同理 `DegradedToIdle / DegradeFailed` 只由宿主产出。

```csharp
public enum SwitchRollResult
{
    /// <summary>已切到新卷，状态仍为 Paused。</summary>
    Completed = 0,

    /// <summary>存在未处理项，需要界面确认是否丢弃。仅控制器使用。</summary>
    NeedsConfirm = 1,

    /// <summary>失败且未动旧卷：仍 Paused，旧卷可继续。阶段 0/1/2 回滚成功后返回。</summary>
    Failed = 2,

    /// <summary>清场中途失败，已 StopAndClear 降级进入 Idle。</summary>
    DegradedToIdle = 3,

    /// <summary>清场失败且降级也失败：线程/数据状态不确定，必须重启软件。</summary>
    DegradeFailed = 4,
}
```

## 6. 宿主实现

### 6.1 三段式 + 回滚，按可回退性切分

```csharp
public SwitchRollResult SwitchFilmRoll(string filmRollName, out string reason)
{
    reason = null;

    // ── 阶段 0：无副作用校验（仍在控制器锁内）
    if (string.IsNullOrEmpty(filmRollName))
    { reason = "膜卷号不能为空。"; return SwitchRollResult.Failed; }
    if (filmRollName == Project.Instance.systemInfo.currentMojuanhao)
    { reason = "新卷号不能与当前卷号相同。"; return SwitchRollResult.Failed; }

    string oldName = Project.Instance.systemInfo.currentMojuanhao;

    // ── 阶段 1：旧卷收尾（任何一步失败都可原样恢复）
    五金模切帧门控.Accepting = false;              // 先断新帧，期间拒绝不计数不告警

    if (!WaitAllIdle(3000))
    { reason = "流程仍在处理当前帧，换卷已中止。"; 五金模切帧门控.Accepting = true; return SwitchRollResult.Failed; }

    if (!AllThreadsAlive(out reason))
    { 五金模切帧门控.Accepting = true; return SwitchRollResult.Failed; }
    // 换卷不停线程：缺一条线程就是脏数据，必须拒绝

    StopResultPublisher();                          // 关键：保证后续写 0 是终值（见 6.4 约束 3）
    DrainStatsOfCurrentRoll();                      // Is_MojuanStart 仍 true，统计落旧卷

    // ── 阶段 2：换目录（失败回滚）
    if (!PrepareFilmRoll(filmRollName, out reason))
    {
        string restoreError;
        if (!RestoreFilmRollAfterPrepareFailure(oldName, out restoreError))
        {
            // 路径/卷号已污染，不能假装旧卷还在 → 降级
            return DegradeToIdle(reason + "；旧卷回滚失败：" + restoreError, out reason);
        }

        Project.Instance.Is_MojuanStart = true;
        五金模切帧门控.Accepting = true;
        StartResultPublisher();                     // 旧队列照常继续发
        return SwitchRollResult.Failed;
    }

    // ── 阶段 3：数据层清场（不可逆，失败由宿主降级）
    if (!ClearDataGeneration(out reason))
    {
        return DegradeToIdle(reason, out reason);
    }

    五金模切帧门控.SetPaused(true);                 // ResetForRun 会清 Paused，必须补回
    五金模切帧门控.Accepting = true;
    Project.Instance.Is_MojuanStart = true;
    StartResultPublisher();
    return SwitchRollResult.Completed;
}
```

### 6.2 回滚与降级辅助

```csharp
/// <summary>PrepareFilmRoll 失败后还原旧卷：卷号、systemInfo、路径指针、PLC 日志路径。</summary>
private bool RestoreFilmRollAfterPrepareFailure(string oldName, out string reason)
{
    // PrepareFilmRoll 已在 NewMujuanhao 之前改了卷号与路径；
    // 只有用旧卷名重跑一次，paramPathSet / PLC 日志路径才会还原。
    if (!NewMujuanhao(Project.Instance.systemInfo.RecipeName, oldName,
                      Project.Instance.systemInfo.CraftType, out reason))
    {
        reason = "恢复旧卷路径失败：" + reason;
        return false;
    }

    Project.Instance.systemInfo.currentMojuanhao = oldName;
    Project.Instance.systemInfo.Save();
    CleanupPreparedFilmRoll();      // 删除本次新建且仍为空的目录
    return true;
}

private SwitchRollResult DegradeToIdle(string cause, out string reason)
{
    string stopReason;
    if (StopAndClear(out stopReason))
    {
        reason = cause;
        return SwitchRollResult.DegradedToIdle;
    }

    reason = cause + "；降级结束也失败：" +
             (string.IsNullOrEmpty(stopReason) ? "未知原因" : stopReason) +
             "。请重启软件后再生产。";
    return SwitchRollResult.DegradeFailed;
}

/// <summary>任一流程线程已停止即返回 false。方向与 ClearBeforeStart 的 HasLiveProcesses 相反。</summary>
private bool AllThreadsAlive(out string reason)
{
    foreach (ProcessServices service in Project.Instance.m_ProcessList)
    {
        if (service == null || service.GetThreadStatus()) continue;
        reason = "流程线程已停止：" +
                 (service.process != null && service.process.processInfo != null
                     ? service.process.processInfo.ProcessName : "未知流程") +
                 "，换卷已中止。";
        return false;
    }
    reason = null;
    return true;
}

/// <summary>排空旧卷统计。Is_MojuanStart 必须仍为 true，路径仍是旧卷。</summary>
private void DrainStatsOfCurrentRoll()
{
    // thd_DataSave 每 500ms 也在排同一队列；两边都出队不会重复写。
    // guard 防止磁盘/PLC 故障时死循环。
    int guard = 0;
    while ((Data.DefectStation_BindingDatasSave.Count > 0 ||
            Data.SizeStation_BindingDatasSave.Count > 0) && guard++ < 50)
    {
        DataSave();
    }
}
```

### 6.3 ClearDataGeneration

取自 `ClearBeforeStart`，去掉 `HasLiveProcesses` 检查、`StopResultPublisher`（已在阶段 1 执行）与发布器启动。

```csharp
private bool ClearDataGeneration(out string reason)
{
    五金模切帧门控.ResetForRun();                     // 清 Paused/丢弃计数（Paused=false 是已知副作用）
    Frame_Core.业务类.五金模切告警.Dismiss("暂停积压已满");

    Data.Init();                                      // 按新卷重建 CSV 路径、清显示/统计/保存队列
    ClearConsecutiveCounts();
    ResetAllResults();                                // 三路写 0（发布器已停，0 是终值）+ 清多次NG
    ClearSizeGroups();

    Project.Instance.baseProDevice.INIPro();
    if (!Project.Instance.baseProDevice.INIProduct())
    { reason = "复位相机参数/序号失败。"; return false; }
    // INIProduct 内：Dispose 各相机算子参数 → 帧序号.Reset()（代际 +1、序号归 1、清在途）

    foreach (PlcResultChannel channel in AllResultChannels) channel.Clear();

    Data.DefectStation_BindingDatasSave.Clear();
    Data.SizeStation_BindingDatasSave.Clear();

    foreach (var item in Project.Instance.M_CameraRelevancies)
    {
        item.Value.Item1.Camera.GrabCount = 0;
        item.Value.Item2.m_ImageSimManage.InitSimFlag();
        item.Value.Item2.m_SizePointInspectionManage.sizePointInspectionParam
            .sizePointInspectionWorkParam.ResetStartDJ();
    }

    if (IsSimulation && Simulation.SimBootstrap.Runtime != null)
    {
        Simulation.SimBootstrap.Runtime.Orchestrator.ClearProducts();
    }

    reason = null;
    return true;
}
```

### 6.4 顺序约束

| # | 约束 | 违反的后果 |
|---|---|---|
| 1 | 排空统计在 `PrepareFilmRoll` 之前 | Prepare 先改卷号并置 `Is_MojuanStart=false`，旧卷统计会写进新目录或直接静默丢失 |
| 2 | `Accepting=false` 在任何清场动作之前 | 暂停态自动模式仍入队，清场中塞进来的帧会落在已清空的计数器上 |
| 3 | `StopResultPublisher` 在 `ResetAllResults` 之前 | 发布器在跑时先写 0 再清队列，在途旧结果会把 0 覆盖成 OK/NG |
| 4 | `INIProduct` 在 `WaitAllIdle` 之后 | 它会 Dispose 算子参数内的图像队列，线程还在用就会崩 |
| 5 | `SetPaused(true)` 在 `ResetForRun()` 之后 | ResetForRun 内 `Paused=false`，漏掉这步换完卷门控按运行态无限积压 |
| 6 | 回滚时先恢复路径、再置 `Is_MojuanStart=true`、最后 `Accepting=true` | 顺序颠倒会让 DataSave 往未恢复的路径写 |
| 7 | `Is_MojuanStart=true` 最后 | 期间 DataSave 若触发会写错归属 |

## 7. 失败语义

| 失败阶段 | 返回值 | 控制器状态 | 旧卷 | 发布器 | 处理 |
|---|---|---|---|---|---|
| 阶段 0/1（校验、等空闲、线程存活） | Failed | 仍 Paused | 完好 | 未停或已恢复 | 可继续旧卷，或修正后重试 |
| 阶段 2（PrepareFilmRoll 失败，回滚成功） | Failed | 仍 Paused | 完好（卷号/路径已还原） | 已重启 | 同上 |
| 阶段 2 失败且回滚失败 | DegradedToIdle / DegradeFailed | 按返回值 | 已污染，不再使用 | 降级时停 | 提示重启或重新开始 |
| 阶段 3（清场中途失败） | DegradedToIdle | Idle | 已损坏 | 停 | 提示"换卷失败，已结束当前膜卷，请重新开始" |
| 阶段 3 失败且 StopAndClear 也失败 | DegradeFailed | 保持 Paused | 不确定 | 不确定 | 提示"请重启软件后再生产" |

原则：**不允许"换卷失败但假装旧卷还在"**。阶段 1 可回退是因为尚未改动任何数据；阶段 2 必须显式回滚；阶段 3 一旦开始就不可逆，直接降级。

## 9. 确认文案

```
换卷会先把旧卷统计落盘，再丢弃以下未处理项；
新卷从第 1 片重新计数。

{pending.ToDisplayText()}

说明：
· PLC 待发送结果中的"含待检"可能已在发布器停止前发出，其余随清场丢弃；
· 合片在途的片不会产生完整统计，也不会再发 PLC 结果。

是否切换到膜卷「{newName}」？
```

要点：措辞是"会先落盘"而不是"已保存"——弹窗出现时排空尚未执行；明确"新卷从第 1 片重新计数"；PLC 结果写"含待检"而不是"全部丢弃"。

## 11. 风险与验证项

1. **算子参数 Dispose 的安全性（地基）**
   流程事件处理函数每帧从 `m_DicCamOperaParam[camID]` 取对象（`五金模切ProDevice.流程内容.cs` 492 / 996 / 1405 / 2398 行）。
   `BaseProParam.Dispose()` 只清队列、复位 `nCurProImgId/nEAId`，不标记对象失效；`DieCutParam.Dispose()` 额外清 `imageInfos/imageEAInfos/BufferSplitLines`。
   Suspend + `WaitAllIdle` 之后调用应安全，但必须在 Harness 与真机"暂停后换卷"各验证一次。

2. **发布器停/起窗口**
   `StopResultPublisher` 会等待发布线程退出（≤2s），期间没有生产者（流程挂起、`Accepting=false`），`EnqueueResult` 的 `_resultPublisher?.Notify()` 对 null 安全。
   阶段 2 失败必须重启发布器，否则旧卷结果永久不发。

3. **确认框停留期间仍会入队**
   Paused 下自动模式继续入队（每相机上限 8）。确认快照不是终态，确认后新到的帧随清场丢弃，与结束膜卷同款。文案已写明"丢弃未处理项"。

4. **DataSave 并发**
   `thd_DataSave` 每 500ms 执行一次 `DataSave`，与排空循环可能同时写同一 CSV。`FileOperationCSV` 使用共享静态 writer，是否线程安全未验证。建议给 `DataSave` 与排空循环加同一把锁（结束膜卷的排空也有同样竞争，属既有隐患）。

5. **仿真在途**
   `帧序号.Reset()` 触发 `OnProductsCleared` 清在途；`ClearDataGeneration` 末尾再显式清一次，覆盖异常残留。

6. **同名目录被手工删除的边角**
   当前卷目录被人工删除后，宿主阶段 0 的"同名"判断会拦住换卷；这属于运维异常，恢复方式是重启或重命名。
